# Booking System — Web Application

Веб-приложение для бронирования рабочих мест на фреймворке Flask. Второй из двух независимых интерфейсов доступа к системе бронирования (первый — Telegram-бот на aiogram, см. отдельный репозиторий), реализован как дипломный проект (ВКР, бакалавриат, ИВТ).

> Веб-приложение и Telegram-бот работают полностью независимо друг от друга: у каждого своя база данных (`booking_webapp` и `booking_bot` соответственно), своя схема таблиц и свой цикл жизни. Это осознанное архитектурное решение — отказ одного интерфейса не влияет на работоспособность другого.

## Возможности

**Аутентификация**
- Регистрация и вход по паре логин/пароль (без email)
- Хеширование паролей алгоритмом PBKDF2-SHA256 (Werkzeug)
- Первый зарегистрированный пользователь автоматически получает статус супер-администратора

**Пользователь**
- Создание бронирования: выбор рабочего места, даты начала и окончания
- Просмотр списка своих бронирований
- Отмена собственного бронирования
- Личный дашборд с последними бронированиями

**Администратор** (дополнительно к правам пользователя)
- Административная панель со сводной статистикой (пользователи, активные брони, места)
- Топ-5 самых популярных рабочих мест
- Просмотр и принудительная отмена любого бронирования в системе
- Журнал действий пользователей (последние 50 записей)
- Добавление и удаление рабочих мест (с принудительным удалением связанных броней при необходимости)

**Супер-администратор** (дополнительно к правам администратора)
- Управление правами пользователей: назначение/снятие статуса администратора
- Права супер-администратора через интерфейс изменить нельзя

**Интерфейс**
- Адаптивная вёрстка на Bootstrap 5
- Переключение тёмной/светлой темы с сохранением выбора в `localStorage`

## Архитектура

Приложение построено по модульному принципу на основе Blueprint-ов Flask, с фабричной функцией `create_app()`.

```
├── run.py                    # точка входа — запуск WSGI-сервера
├── config.py                 # конфигурация приложения (из переменных окружения)
├── app/
│   ├── __init__.py           # create_app(), регистрация Blueprint-ов
│   ├── models.py              # модели SQLAlchemy: User, Workplace, Booking, Log
│   ├── auth.py                # Blueprint: регистрация, вход, выход
│   ├── utils/
│   │   └── decorators.py      # admin_required, super_admin_required
│   └── routes/
│       ├── main.py            # Blueprint: главная страница, дашборд
│       ├── bookings.py         # Blueprint: создание/отмена бронирований
│       ├── workplaces.py        # Blueprint: управление рабочими местами
│       └── admin.py            # Blueprint: административная панель
├── templates/                 # Jinja2-шаблоны (base, dashboard, bookings, admin ...)
├── requirements.txt
└── .env.example
```

| Blueprint | URL-префикс | Назначение |
|---|---|---|
| `auth` | `/auth` | Регистрация, вход, выход |
| `main` | `/` | Главная страница, дашборд |
| `bookings` | `/bookings` | Создание и отмена бронирований |
| `workplaces` | `/workplaces` | Управление рабочими местами |
| `admin` | `/admin` | Административная панель |

## Схема базы данных

База данных `booking_webapp`, структура описана декларативно в `models.py` и применяется через миграции Flask-Migrate.

| Таблица | Поле | Тип | Описание |
|---|---|---|---|
| **users** | `id` | INTEGER (PK) | Автоинкремент |
| | `username` | VARCHAR(64), уникальное | Логин |
| | `password_hash` | VARCHAR(255) | Хеш пароля (PBKDF2) |
| | `is_admin` / `is_super_admin` | BOOLEAN | Флаги прав |
| | `created_at` | DATETIME | Дата регистрации |
| **workplaces** | `id` | INTEGER (PK) | Идентификатор места |
| | `name` | VARCHAR(100), уникальное | Название |
| | `created_at` | DATETIME | Дата добавления |
| **bookings** | `id` | INTEGER (PK) | Идентификатор брони |
| | `user_id` / `workplace_id` | INTEGER (FK) | Связи с users / workplaces |
| | `start_date` / `end_date` | DATE | Период бронирования |
| | `created_at` | DATETIME | Время создания |
| **logs** | `id` | INTEGER (PK) | Идентификатор записи |
| | `user_id` | INTEGER (FK → users) | Кто выполнил действие |
| | `action` | VARCHAR(255) | Описание действия |
| | `created_at` | DATETIME | Время записи |

Связи `User → Booking` и `Workplace → Booking` объявлены с `cascade='all, delete-orphan'`, что обеспечивает каскадное удаление зависимых броней.

### Предотвращение конфликтов бронирований

Проверка пересечения дат реализована средствами ORM SQLAlchemy — логика эквивалентна оператору `OVERLAPS`, используемому в версии для Telegram-бота:

```python
conflict = Booking.query.filter(
    Booking.workplace_id == wp_id,
    Booking.end_date >= start_dt,
    Booking.start_date <= end_dt
).first()
```

Корректно обрабатывает частичные пересечения и полное поглощение одного интервала другим.

## Установка и запуск

### 1. Клонирование и виртуальное окружение

```bash
git clone https://github.com/<artoutsaur>/booking-system-webapp.git
cd booking-system-webapp
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Настройка базы данных

```sql
CREATE DATABASE booking_webapp;
```

### 3. Переменные окружения

Скопируйте `.env.example` в `.env`:

```
DATABASE_URL=postgresql://user:password@localhost:5432/booking_webapp
SECRET_KEY=your_secret_key_here
```

### 4. Применение миграций

```bash
flask db upgrade
```

(Если запускаете проект впервые и миграций ещё нет — `flask db init && flask db migrate -m "initial" && flask db upgrade`.)

### 5. Запуск

```bash
python run.py
```

Приложение будет доступно на `http://127.0.0.1:5000`.
